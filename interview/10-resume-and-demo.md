## 简历条目（推荐个人项目口径）

**Simple Code — 终端 AI 编程助手（个人项目）**

一句话：自然语言驱动的本地 Coding Agent，模型只负责决策，工程层负责工具协议、权限、上下文预算和中断恢复。

**职责（挑 3 条，别堆）：**

- 独立设计交互 / 引擎 / 工具 / 记忆 / 安全五层，实现 Agent Loop 与双协议流式适配
- 实现工具 schema 校验、危险命令与路径沙箱、规则与 HITL；无人值守路径遇确认自动拒绝
- 实现大结果落盘 + 自动摘要，压缩与中断时保持 tool_use / tool_result 成对

**亮点（每条：做了什么 + 为了什么。没测过的数字不要写）：**

- **双协议归一：** Anthropic / OpenAI 流式事件收成统一 StreamEvent，Agent 与 TUI 不绑一家 SDK
- **协议完整性：** 取消、异常、发送前补齐或清理半截工具调用，避免下一轮 API 直接失败
- **渐进压缩：** 超长工具输出落盘引用；近窗口再摘要并熔断，避免压缩失败死循环烧钱
- **五层权限：** 危险命令与沙箱不可被 YOLO 绕过；TUI 默认可写文件、命令再确认
- **MCP 延迟加载：** 外部工具默认不占满 schema，ToolSearch 后再展开
- **先读后改：** EditFile 未读或读后文件变化则拒绝写入，降低覆盖用户改动

社招若包装成「内部提效」，必须你真的在团队用过。没用过就写个人项目。

不要写「课程项目」。课程是学习途径，不是项目属性。

## 演示 2 分钟（面试官让你跑起来时）

提前录也行。现场脚本：

1. 打开仓库，`simplecode`，指状态栏：模型、目录、模式。
2. `/plan`：让它只读，出一份小改动计划（不要当场重构半个系统）。
3. `/do`：接受计划，看它 Read → Edit → 必要时 Bash 测。
4. 指一次权限或一次工具卡：说明「写可以直接，毁坏性命令会问」。
5. 提一句 CH16：如果我在它读完后手改文件，它会拒绝覆盖。
6. 停。不要演示 Team 除非他追问——容易超时翻车。

备用：`-p` 无人值守跑一句只读任务，说明不会弹窗挂死。
