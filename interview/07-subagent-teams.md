# 07 子 Agent、Worktree、Team：一个人不够的时候

## 什么时候需要第二个 Agent

单 Agent 两个瓶颈：

1. **窗口：** 三十个文件的读写全挤在一段历史里，后面会忘前面。
2. **串行：** 互不依赖的模块也只能一个个改。

子 Agent 不是「再 new 一个 LLM」，而是**有边界的工人**：自己的对话、自己的工具子集、自己的权限（通常不能弹窗）、可选自己的目录。主线程只要结论，不要它读文件的噪声。

本仓库内置类型：`Explore`（只读摸仓库）、`Plan`、`general-purpose`、`verification`。还有 fork：从当前对话分叉，但子 Agent **不能再 fork**，防递归爆炸。

小任务别开群：每个工人都要重新理解项目，token 总账更贵，协调还会出错。

---

## Worktree：解决「两个人同时改一个文件」

多个 Agent 对同一工作区写，必冲突。

Git Worktree = 同一仓库多一份检出目录、各自分支。每个子 Agent 的 Read/Write/Bash 绑在自己的 `work_dir`，**不用 `chdir`**，避免前台后台互相踩。

做完：没改动的树可以删；有改动的保留路径/分支，让人合并。脏树默认不删，防止丢活。

和 Docker 比：隔离的是**文件**，不是网络/系统。对「并行改代码」够了，合并还能走 Git。面试被问 Docker 就诚实说：我选的是文件系统隔离 + 原生合并，没做容器网络隔离。

## Team 和邮箱

两种协作：

| | 像什么 | 何时用 |
|---|---|---|
| Coordinator | 技术负责人拆活、验收，自己不写业务代码 | 有依赖、要人盯全局 |
| 平等 Team | 各认任务清单，邮箱松散同步 | 长期各守一块（前端/后端） |

通信用**文件邮箱**，不用直接函数调用：

- 调用是同步阻塞，对方挂了整条链挂
- 跨进程 / 跨 worktree 更别提直接 call
- 邮箱：写成 JSON 文件就返回；对方 Loop 开头自己读。对方不在线也不丢

没有 RPC「我卡住等你回」。要等结果：发完继续干，下一轮看邮箱；或 Coordinator 轮询任务完成通知。

踩过的坑（很好讲）：

- Worker 把别人的进度广播当成新指令，把活干第二遍 → 消息要带类型：任务 / 状态 / 关机
- 摘要把「做了一半」写成过去时，Coordinator 误判完成 → 不能只看「他说做完了」，要看产出和测试
