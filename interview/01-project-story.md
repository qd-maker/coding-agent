# 01 项目故事：先让面试官看见画面

## 一句话

Simple Code 是一个**终端里的 AI 编程助手**：你用自然语言下任务，它自己读代码、改文件、跑命令，循环直到做完或被你打断。

它不是网页聊天框，也不是「调一次 LLM 返回一段代码」。它是一个**受约束的状态机**：模型提出下一步，工程系统负责校验、权限、执行、回写结果、决定是否继续。

## 三十秒（先背这个）

> Simple Code 是我做的终端 AI 编程助手。用户说一句自然语言，Agent 自己读仓库、改文件、跑命令，不需要人盯每一步。底层拆成交互、引擎、工具、记忆、安全五层，同时接 Anthropic 和 OpenAI 兼容协议。我做它是因为每天在用这类工具，但内部怎么决策像黑盒，想自己从零走通一层。

## 三分钟成长故事（展开时用）

不要按目录念五层。按「上一层暴露了什么问题，所以加下一层」讲。

1. **先让它开口。** `client.py` 接上流式 API，TUI 里字一个个出来。这时它只是聊天机器人。
2. **给它手。** `ReadFile / WriteFile / EditFile / Bash / Glob / Grep`。能干活了，但做一步就停，等人催。
3. **给它循环。** `agent.py` 里：有 `tool_use` 就执行再问模型，没有就停。从这儿开始才叫 Agent。
4. **告诉它是谁。** `prompts.py` 组装 System Prompt：身份、规则、语气。同样的工具，提示词不同表现完全不同。
5. **装刹车。** 它能跑 Bash。危险命令正则、路径沙箱、规则、模式、弹窗确认，一层 deny 就停。
6. **打开门。** MCP 把外部工具接进来；Skill 是按需说明书；Hook 是确定时机跑确定动作。
7. **省钱和记事。** 长任务历史会爆窗口：大结果落盘 + 超阈值摘要。跨会话用 `SIMPLECODE.md`、JSONL、自动记忆。
8. **一个人不够。** 子 Agent 隔离上下文；Worktree 隔离文件；Team + 邮箱做异步协作。

收尾把选择权给他：

> 整体就是这样长出来的。技术上我比较想被问的是：工具调用怎么保证成对、上下文怎么压还不把协议压坏、权限为什么不能只写在 Prompt 里。

## 三种第一反应怎么接

### 「所以就是照着 Claude Code 做的？」

承认参考，立刻给差异和边界。

> 功能形态对标这类终端 Agent，代码是按同一套架构理念在本仓库独立实现的。Claude Code 是闭源产品（即便有过快照，也不等于我在维护官方实现）。我这边从第一天就做了 Anthropic / OpenAI 两套流式协议归一；权限、压缩、MCP 延迟加载都在 Python 里自己落地。差距我也很清楚：没有 LSP、没有官方工具市场、没有产品级几千个边角。我能说清差距，是因为我走过从原型到「还能缺什么」这一段。

### 「一个人做的？代码是 AI 写的吗？」

> 独立负责设计和实现。开发时大量用 AI 编程助手，等于用 Agent 造 Agent。具体行很多是生成的，但五层怎么切、权限为什么不能被 YOLO 绕过危险命令、压缩为什么必须对齐 tool 配对，这些是我拍的板。AI 加速实现，替代不了取舍。

### 「有用户吗？生产在跑吗？」

不要编。

> 这是学习型、可演示的工程原型，目标是把 Coding Agent 控制面走通，不是卖产品。和商业产品的差距不在「有没有 Loop」，而在细节覆盖：流式工具、检查点回滚、鉴权市场、长期稳定性。能说清这段距离，比假装已经是产品更像工程师。

## 本仓库里你可以当「钩子」的真实点

讲故事时丢钩子，不要一次讲透：

- **不看 `stop_reason`，看有没有 tool_use**（`agent.py`）
- **EditFile 必须先读过，文件被你改过就拒绝覆盖**（CH16）
- **取消/异常会补齐 synthetic tool_result**，下一轮不会协议报错
- **MCP 默认延迟加载**，先 `ToolSearch` 再展开 schema
- **无人值守（`-p`）遇到确认直接拒绝**，不会挂死
- **子 Agent 不能弹窗**，ask 变 deny

这些都是本仓库里有代码、有测试的，比空泛「我做了 Agent」硬。
