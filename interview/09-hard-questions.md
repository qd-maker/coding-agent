# 09 尖锐追问：信用靠诚实

这些题决定面试官把你标成「真做过」还是「背了课」。

---

## 「不就是照着 Claude Code 抄的吗？」

不要怒、不要装首创。

> 形态对标，实现独立。我学的是控制面：Loop、工具协议、权限、压缩、恢复。官方闭源，快照也会过时。我的每一层能指到本仓库文件。差异例如：双协议从第一天就归一；MCP schema 在客户端展开，兼容非 Anthropic 端点；EditFile 做了先读后改和外部修改检测。我也能列出我没做的：LSP、OAuth 市场、文件检查点 undo、流式边生成边跑工具。能画这条线，说明我知道原型和产品的距离。

---

## 「代码都是 AI 写的，你凭什么写进简历？」

> 行很多是生成的。简历写的是我做的决策和我能维护的系统。你现在指定改权限优先级或配对修复，我能打开对应测试和实现讲。判断力在取舍和排坑，不在是否用了自动补全。

---

## 「五层为什么不是三层？」

> 最早几乎只有弹窗，体验不可用，才把「明显禁止 / 明显安全」抽成代码层。危险命令和沙箱必须独立且不可被模式放行，否则 YOLO 就等于没安全。规则层给项目/个人可配置；模式层是一键策略；HITL 只剩灰区。少一层就得把「绝对不能做的」和「看情况的」混在一起，要么误拦要么误放。

---

## 「正则一定漏网，怎么办？」

> 正则是尽力而为。`python -c` 里嵌 rm 可能漏。所以后面还有沙箱（文件类）、HITL、以及 Bash 不走「只因字符串像读就可以并行」。安全是多层，不赌第一层完美。

---

## 「有实际用户 / 性能数据 / 85% 吗？」

没有实测就不要说。

> 延迟加载的动机是工具一多 schema 先吃窗口。我可以现场推：N 个 MCP 工具 × 平均 schema 长度。精确百分比我没在论文级实验里报，简历里我写成「按需展开 schema，避免首轮被工具定义占满」。

---

## 「如果重做，改什么？」

准备 3 条真实的（本仓库也确实还缺）：

1. 模型还在吐字就开始跑只读工具，降低等待。
2. 历史给 UI 留全量，给模型另做投影，压缩别直接改用户看见的会话。
3. 多 Agent 要有一块能看见每个工人在干什么的面板，现在排错靠日志。

不要说「挺完美没啥改的」。

---

## 「最大的失败？」

挑一个你真排过的。若还没，用仓库里已修过的：

> 流式界面停在半句：字已经到了，40ms 节流加上立刻开跑工具，屏幕不刷新。用户以为卡死。修法是离开文本事件立刻刷尾巴。教训是：Agent 的「在跑」必须让人看见，否则不可用。

或：

> 中断后下一轮 API 报配对错误。才理解对话历史是有外键的协议，不是聊天记录。

---

## 本仓库相对「真正天天用的 coding agent」还缺什么

面试被问「还差啥」时用这张表，显得清醒：

| 缺的 | 用户体感 |
|---|---|
| 边生成边跑工具 | 长回复干等 |
| 检查点 / undo | 改坏了回滚费劲 |
| LSP / 诊断 | 不如 IDE 里改得准 |
| 浏览器 / 截图 / 多模态真用 | 前端活要靠外部 MCP，还不够顺 |
| MCP 资源与 Prompt 目录 | 现在主要接了 tools |
| 官方市场与一键登录 | 配置门槛高 |
| 长期记忆去噪 | 会记脏，靠人改文件 |
| Team 可视化与合并策略 | 能跑，但还不像团队产品 |

说完接一句：CH16 我优先补的是「少覆盖用户文件、取消不断档、无人值守不挂、上下文爆了能缓」，因为这比再堆 Skill 更能让人敢用。
