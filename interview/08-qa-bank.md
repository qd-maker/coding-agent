# 08 高频题库（按本仓库改过的口述）

用法：盖住「答」，自己说完再对。每题至少口述两遍。细节章节见链到的 02–07。

---

## A. 定位与本质

**1. 一两句说清项目？**  
终端 AI 编程助手。自然语言下任务，Agent 自己读改跑，人不用盯每一步。我做它是为了把这类「黑盒 Agent」的控制面自己走通。  
追问「已有 Claude Code」→ 见 [09](09-hard-questions.md)。

**2. Agent 必要元素？**  
四个：LLM（决策）、工具（动手）、循环（多步）、反馈（结果驱动下一步）。  
安全、记忆不是「能不能跑」，是「敢不敢用、好不好用」。

**3. 有哪些工作模式？本仓库用了啥？**  
ReAct：Loop 默认。Plan-and-Execute：`/plan` 再 `/do`。Multi-Agent：Team / Coordinator。  
Reflection 没独立做：测试和完成门当硬反馈，比再烧一轮「自己审自己」更值。特定高风险改动以后可以加。

**4. 怎么知道该停？停不下来呢？**  
看有没有 tool_use，不看 stop_reason。兜底：最大轮次、连续未知工具、压缩熔断、用户取消、完成门。详见 [03](03-agent-loop.md)。

**5. 五层怎么分、为什么？**  
交互 / 引擎 / 工具 / 记忆 / 安全。为了换 UI、换模型、加工具时 Loop 不动。易错边界：压缩 vs 注入；邮箱必须在每轮模型前消费。[02](02-architecture.md)。

## B. 协议与 Loop

**6. Function Calling 长什么样？**  
请求带工具 schema；模型回 tool_use（名、id、参数）；宿主执行；同一 id 回 tool_result；再请求。模型从不真调外部接口。

**7. 一次三个 tool_use？**  
按 `is_concurrency_safe` 相邻分批：只读并行，写/命令串行，不打乱模型顺序。[04](04-tools-and-permissions.md)。

**8. ReAct 和大白话 LLM 调用差在哪？**  
单次问答 vs 想–做–看–再想。历史里带着自己的行为和结果，基于事实决策。选错工具：把 is_error 回传，让它下一轮改；连续错就改描述/Prompt。

**9. 一轮 Loop 按顺序？**  
收邮箱 → 刷新环境 → 结果预算 → 可能摘要 → 调模型 → 无工具则结束（或验证）→ 有则 hook/权限/执行/回写 → 下一轮。[03](03-agent-loop.md)。

**10. 并行怎么判断？慢工具拖垮整批？**  
工具自己声明。批次内等最慢的。每工具有 timeout。没做「批次内取消兄弟」（Claude Code 对 Bash 有，我们没做到产品级）。

## C. 计划、工具、权限

**11. Plan Mode 为什么要？**  
大改先只读出方案，人看一眼再动手，避免理解偏了改爆接口。计划落盘，退出时回灌。允许执行中偏离，但应说明；审计靠历史回放。

**12. 新加工具改几处？**  
继承 Tool，register。Schema、权限类别、并发都从声明来。MCP 连上包装即注册。要 LLM 的工具构造时注入。

**13. grep 出 50MB 怎么办？**  
单条/聚合超限落盘留预览。预览按行切。会话目录结束可清。宁可多一轮 ReadFile，不要撑爆窗口。[05](05-context-memory.md)。

**14. 五层权限从内到外？**  
危险命令（不可被 YOLO 放行）→ 路径沙箱 → 规则 YAML → 模式矩阵 → HITL。任一层 deny 短路。[04](04-tools-and-permissions.md)。

## D. MCP / 压缩 / 记忆

**15. 为什么要 MCP？**  
工具与 Loop 解耦、配置即生效、凭证可放在 Server 进程。失败降级。[06](06-mcp-skills-hooks.md)。

**16. 通信方式？**  
本仓库：stdio + Streamable HTTP。业务只认 list/call。本地能跑的走 stdio，延迟小、不用认证。

**17. Server 挂了？延迟加载？**  
注册隔离，失败记下来继续。调用时尝试重连，再失败当工具错误回给模型。延迟加载：默认不塞完整 schema，ToolSearch 后再展开。数字自己测了再写简历。

**18–19. 压缩怎么做？摘要自己也超长？**  
落盘再摘要。阈值先扣摘要预算。失败丢最早整轮、最多 3 次、然后熔断。多次摘要会失真，原始 JSONL 还在。[05](05-context-memory.md)。

**20–21. 记忆为什么分层、何时注入？**  
用户级跨项目，项目级跟仓库。会话开头注入一次，压缩后重注。人可直接改 md。

## E. 多 Agent

**22. 单 Agent 不够？两种模式怎么选？**  
窗口 + 串行。Coordinator 管依赖；平等 Team 管长期分片。小任务别开群。[07](07-subagent-teams.md)。

**23. 为什么邮箱不是直接调用？**  
不阻塞、跨进程、可落盘。没有同步 RPC；要编排用 Coordinator 轮询完成通知。

**24. 最大工程挑战？**  
确定性（配对、分批、权限）和模型不确定性缠在一起。多 Agent 误判、压缩语义失真，单测难覆盖，得回放 JSONL。

## F. Skill 与「为什么要工具/记忆」

**25. Skill / MCP / Function Calling？**  
协议 / 工具箱 / 说明书。Skill 白名单收工具，不新增能力，也不能代替权限。

**26. 为什么要工具？越多越好吗？**  
没工具只能贴代码聊天。工具让它自己取真实状态。内置保持少而精，专业能力 MCP 按需。描述质量比数量重要。

**27. 为什么要记忆？和 SIMPLECODE.md？**  
会话内靠历史；跨会话靠记忆。指令是人写的规范，记忆是抽出来的偏好。

## G. 对比、踩坑、AI 编程习惯

**28. 和 Claude Code 比？**  
见 [09](09-hard-questions.md)。骨架同类，差在细节和生态。我们多协议、代码可审计；他们有 LSP、市场、检查点。

**29. 最大的坑？**  
tool_use / tool_result 配对被中断、恢复、压缩破坏。后来：取消补结果、发送前配对、压缩按轮切。

**30. 做 Agent 最难？**  
确定性和不确定性混在一起。表面上工具死循环，根因可能是摘要丢了「已经读过」。工程层越硬，排查范围越小。

**31–35. AI 工具怎么用？**  
按你真实习惯说：Plan 再 Code；一个功能一个会话；CLAUDE.md/SIMPLECODE.md 写短、写测试命令；大包大揽会返工；架构决策人拍板。正确性靠测试 + 看 diff 的异常路径 + 必要时新开会话审查。不要编没用过的产品。
